## UI Standards & Theming

- **App Theme**: Uses `AppTheme`, `ThemeConfig`, and `ThemeFactory` in `cb_file_manager/lib/config/` to generate `ThemeData`.
- **Hybrid Design**: 
    - **Material 3**: Used as the base design language.
    - **Fluent UI**: `FluentThemeConfig` adapts Material tokens to Fluent UI for Windows-specific components, ensuring a native feel on desktop.
    - **Flat Philosophy**: Avoids borders and heavy elevations; prefers subtle shadows and opacity layers.
- **Mobile Galleries**: `ui/screens/media_gallery/` uses flat cards and reuses `MobileFileActionsController` for top action bars.
- **Desktop Preview Mode**: File browser supports `ViewMode.gridPreview` with a resizable right preview pane (video/image via existing viewers, PDF via `pdfx` `PdfView`).

## Windows Acrylic Composition

- Primary Windows startup holds `SWP_SHOWWINDOW` during native maximize, loads the saved `ThemeProvider.ready`, and waits for `waitUntilFirstFrameRasterized`. It installs the selected backdrop while hidden and then reveals the complete frame. This prevents maximize from exposing an empty HWND and removes the old visible 120 ms gap before acrylic. E2E startup, background torrent launches, PiP and dedicated players keep their own visibility paths.
- Windows backdrop updates from Dart are single requests; native delegates own recovery. Do not restore Dart retry bursts or repeat frame/style changes after showing the window.
- Dynamic Windows Acrylic uses one root `ACCENT_ENABLE_ACRYLICBLURBEHIND` policy, with the system backdrop/host brush disabled. It must never be overwritten by a root transparent-gradient accent. Native tint alpha is the required nonzero minimum (`1/255`); Flutter owns the visible tint and strength. This avoids stacking an extra opaque native tint over the app. Mica keeps its DWM path; rejected acrylic accents fall back to the system acrylic material alone. Accent flag/tint handling follows [window-vibrancy's implementation](https://github.com/tauri-apps/window-vibrancy/blob/dev/src/windows.rs).
- The Windows/Linux appearance control displays **Acrylic transparency, 0–100%** in 1% steps; lower values make the background more opaque. Existing `desktop_acrylic_strength` preferences remain on their 0–2 scale (`1` displays as 50%). `DesktopAcrylicTheme` maps the full stored range to bounded opacity values shared by both hosts and `FluentSurfaceTokens`. At 0%, canvas, content, toolbar and drawer are opaque; raising transparency reveals the backdrop progressively, with a denser drawer. Dialogs and menus remain opaque. Preview updates Flutter tint only, and slider release persists the value. macOS keeps its separate Glass controls.
- Acrylic slider drag values and percentage labels update locally. App-wide previews coalesce to the latest value every 80 ms, rather than rebuilding the host themes on every pointer event. Release cancels any pending preview and commits immediately; leaving the control cancels pending callbacks. `ThemeConfig` reuses up to eight immutable base themes keyed by brightness, accent, text colour, font and target platform, so backdrop previews do not rebuild typography and component styles. Tests cover drag/commit/disposal timing and cache separation for appearance/platform changes.
- The Windows browser shell keeps the runner's native title fixed at `CB File Hub`. Tab selection updates the Flutter tab strip and peer registry, without sending `WM_SETTEXT` or changing native caption styles. This avoids disturbing live acrylic on each tab switch. Other platforms retain their active-tab window titles. Do not temporarily remove `WS_CAPTION` to update a live acrylic window's title.
- Resize/maximize recovery waits for Flutter's actual resized frame (`FlutterEngine::SetNextFrameCallback`) instead of assuming a timer runs after presentation. `ResizeFrameSync` blocks early repairs, rejects superseded callbacks and ignores unchanged sizes. After the matching frame the native delegate repairs the root acrylic accent and alpha in place, without clearing the accent or toggling the system material. This repair is allowed during the size/move loop, so dragging a maximized window down does not wait until mouse-up to restore blur. Only the system-material fallback waits for that loop to end. Unchanged retries do no native work, including on Windows 10.
- Dependency check: the app uses `window_manager 0.5.2` and `fluent_ui 4.17.0`, with an app-owned Windows backdrop implementation (no `flutter_acrylic` dependency). Published `window_manager 0.5.2` has no startup-acrylic fix in its changelog; upstream `main` describes a breaking 0.6.0 nativeapi migration. `flutter_acrylic 1.1.4` fixes Windows 11 title-bar rendering, not this startup sequence. References: [window_manager changelog](https://pub.dev/packages/window_manager/changelog), [upstream changelog](https://github.com/leanflutter/window_manager/blob/main/CHANGELOG.md), [flutter_acrylic changelog](https://pub.dev/packages/flutter_acrylic/changelog).

- `window_backdrop.h` restores the root material separately from the Flutter child's optional transparency. Activation invalidates composition; once repaired, repeated requests leave both surfaces untouched. Failed repair remains pending for the next retry. Windows may reject child-HWND accent policies even when the root succeeds; this compatibility failure must not invalidate the working root. `window_backdrop_test.cpp` covers exclusive root backends, native tint alpha, repairs without intervening clears, idle no-ops, unsupported children, fallback and complete API failures.
- window_manager's top-level delegate is registered before `WindowUtilsPlugin` and consumes `WM_SIZE(SIZE_MINIMIZED)`, `WM_NCACTIVATE` and `WM_EXITSIZEMOVE`. The backdrop delegate therefore detects minimizing from `WM_WINDOWPOSCHANGED` (state-changed flag), and holds material rebuilds until the size/move loop ends, polling `GUI_INMOVESIZE` because `WM_EXITSIZEMOVE` never reaches it. A child accent rejected during a rebuild is remembered as unsupported, so activations do not retry it. After `WM_DWMCOLORIZATIONCOLORCHANGED`, which the runner answers with the system dark mode, the delegate restores the app's dark mode without rebuilding the material.
- Backdrop updates invalidate paint asynchronously, after root and child settings are applied. They must not use `RDW_UPDATENOW` or `RDW_ERASENOW`, which expose intermediate composition state.
- Run `scripts/test_windows_backdrop.ps1` and `scripts/test_windows_custom_frame.ps1` from Visual Studio Developer PowerShell for native regression coverage. These tests verify API transitions and frame behavior; live moving-background and in-app animation checks are still required to establish visual stability on a Windows GPU.
- For a live native trace, set `CB_BACKDROP_TRACE_FILE` to an absolute writable log path before `flutter run -d windows --release`. The opt-in log records PID, root/view HWNDs, visibility/maximize/minimize, foreground/activation, extended window styles, pending frame state and native backdrop state; it does not record tab titles or file names. A successful material request is not pixel validation. Some DWM attributes are set-only or unsupported on child HWNDs, so getter HRESULTs alone must not be treated as failed composition. Verify the running executable's path/version too: the installed app and local build can differ.
- Before the exclusive-accent change, the transition to solid reproduced with both Skia and Impeller. A debug render-tree dump showed the full-window Material retaining alpha `0.306`, with transparent Home scaffolds. The user confirmed failure while actively using the window; foreground traces showed an active maximized window with material `3` and no pending resize. This ruled out attributing that case solely to inactive-acrylic fallback. Live visual verification of the replacement accent path remains required; passing API tests is not visual verification.

## macOS Materials and Panel Motion

- `FluentChromeSurface` composites tint, blur and a subtle macOS edge in Flutter. Interactive surfaces never embed decorative `AppKitView` widgets: the engine's native platform-view containers have their own hit testing, independent of Flutter's `IgnorePointer` or a child NSView returning `nil`.
- Desktop appearance branches by OS: Windows retains Acrylic; macOS uses Glass. `ThemeProvider.desktopBackdropStrength` selects the correct preference. macOS seeds `desktop_glass_strength` from the legacy acrylic setting once, then persists it independently. Preview changes commit on slider release, including when the committed value equals the preview.
- `MacosGlassTheme` separates the 0–200% transparency and blur controls for both host themes, canvas, toolbar, drawer, panels and wallpaper. Transparency zero paints opaque surfaces. Content surfaces retain more tint than chrome, and every text-bearing surface increases its tint when necessary to protect primary/secondary text against black or white backdrops. The minimum contrast is 4.5:1, or the authored opaque contrast for intentionally muted palette tones. Blur alone cannot protect contrast against broad bright/dark areas.
- Glass blur persists independently as `desktop_glass_blur_strength` and updates Flutter chrome/wallpaper blur without changing transparency. Dynamic mode blends with the actual desktop/windows behind the app; wallpaper mode uses the selected image. AppKit owns the native blur kernel; no private blur-radius API is used.
- `WindowAcrylicService` configures a native `NSVisualEffectView` behind the Flutter content through the existing `cb_file_manager/macos_window` channel. The backdrop cannot receive mouse events. Wallpaper mode removes it and keeps the user-selected image.
- `FluentSurfaceTokens` shares title-row, traffic-light and sidebar geometry. macOS uses a 60-point title row, wider rounded tabs and an inset sidebar with compact navigation rows and neutral selection. Windows retains its existing geometry and selection rail.
- `CbPanelReveal` owns retained opening/closing transitions for the AI sidebar and Status Center. Closing immediately disables input and focus, then releases the child after the exit finishes. Reopening reverses the transition. Reduced motion skips the animation; high contrast uses opaque chrome without blur.
- Native material changes require a rebuilt macOS app. Widget tests cover input, absence of decorative platform views, theme changes, panel lifecycle and interrupted/reduced motion. They do not establish native mouse routing or appearance in the running macOS app.

## macOS Sidebar Favorites

- The existing pinned section becomes Favorites on macOS. Foundation resolves Applications, Desktop, Documents, Downloads, the user's home, Pictures, Music and Movies through `getSidebarUserFolders`; only existing directories are offered. Other platforms retain manual pins.
- `SidebarPinsRepository` seeds these paths once, merging existing pins without duplicates. The paths and `macos_sidebar_defaults_v1` marker commit in one SQLite transaction, shared with manual pin mutations. The JSON path-list format remains compatible with context menus, other windows and backups. An unavailable folder is never deleted merely by validating the list.
- The first seed opens Favorites for existing accounts; later collapse state and removals persist. Both sidebar renderers use `SidebarPinnedEntry` for localized labels and folder-specific icons, and keep navigation on the existing tab path flow.

## Home Privacy

- Settings > Interface > Show recent folders on Home controls the "Pick up where you left off" section. The SQLite preference `show_recent_folders_on_home` defaults to true for existing behavior and is retained across launches.
- Home hides recent folders until the preference is loaded. Turning it off clears displayed paths and previews immediately, skips reading recent paths and prevents in-flight requests from restoring them. Media cards remain available with library metadata; recent directories are no longer passed as preview inputs.
- This setting hides Home history only. It does not delete browsing history, disable history collection, or change the separate tab workspace restore setting.
